## Dispatcher Architecture

`pymagatama/mcp_dispatch.py`:

- `_DEFAULT_ACTORS` is a list of dicts. Three resolution patterns:
  - **default convention**: `pymagatama.<actor>_worker_main:task_<snake>`
  - **fn_template override**: per-actor `module` + `fn_template` for
    primitives that live elsewhere (e.g. aria_signal, shosha, isbn)
  - **explicit mapping**: per-method dict for heterogeneous actors
    (e.g. wellbecoming spans 4 sub-modules)
- 3 override builders: `_build_const_overrides` / `_build_audit_overrides`
  / `_build_llm_overrides` register `com.etzhayyim.tools.*` namespace tools.
- Tool functions are imported lazily; missing modules WARN-and-skip
  (boot stays robust).

Resolver path (langgraph_node_resolvers):

```
mcp://<nsid>
  → SELECT actor_host FROM vertex_mcp_tool_def WHERE nsid=$1 AND enabled=true
    (60s in-process cache)
  → POST https://{actor_host}/xrpc/com.etzhayyim.mcp.message
    body = {"method":"tools/call","params":{"name":"<nsid>","arguments":{...}}}
  → Worker proxies to dispatcher /xrpc/com.etzhayyim.mcp.message
  → mcp_dispatch.handle_envelope → MCP_HANDLERS[nsid] → task_*
  → result wrapped in {"result": ...}
  → returned to LangGraph node → state[result_key]
```

End-to-end smoke test (no DB / no HTTP): `tests/test_mcp_e2e_smoke.py`.

## How to extend (new actor)

For an actor whose `task_*` functions already exist:

1. Add a dict entry to `_DEFAULT_ACTORS` (`actor`, `methods`, optional
   `module` + `fn_template`, or `mapping`).
2. Add a regression test (one of the existing per-actor tests as template).
3. Author SQL migration: vertex_mcp_tool_def seed + assistant.v2 +
   mcp_tool nodes + supersedes UPDATE.
4. (Eventually) author proper lexicons under
   `00-contracts/lexicons/com/etzhayyim/apps/<actor>/`.
5. (Eventually) deploy `<actor>.etzhayyim.com` Worker matching saikin/ki template.

The dispatcher will auto-wire after step 1; the data layer responds
after step 3 is applied.
