## Findings that should propagate into R1 ADRs

These are concrete constraints discovered through preflight that R1 ADR
drafters need to encode:

1. **libLLVM is a build-time dependency for Mitsuba 3 differentiable rendering.**
   Even `scalar_rgb` variant fails without `libLLVM.dylib` reachable via
   `DRJIT_LIBLLVM_PATH`. The R1 ADR for Kusawake (or any actor binding R1
   sim) must include libLLVM provisioning in the Murakumo node setup. This
   is compatible with G1 (`brew install llvm` is Apache-2.0).

2. **MuJoCo MJX has unimplemented geom-pair collisions** (notably
   `cylinder × box`). Workaround: use `capsule` for wheel geometry in any
   MJCF intended to run under MJX. Two MJCF variants now exist:
   `kusawake.xml` (cylinder wheels — C++ MuJoCo + interactive viewer) and
   `kusawake_mjx.xml` (capsule wheels — MJX-compatible). R1 ADR should
   either (a) standardize on capsule wheels for MJX-bound actors, or
   (b) gate MJX use on a per-actor geometry audit.

3. **JAX CPU is slower than MuJoCo C++ at small batch sizes.** On Apple
   Silicon, 16× parallel MJX rollout on CPU takes ~20 ms/rollout vs C++
   2.3 ms/rollout (0.1× speedup). The GPU/TPU advantage of MJX only shows
   up on accelerator devices. R1 ADR should bind MJX execution to Murakumo
   EVO-X2 ROCm (per ADR-2605215000) and measure the speedup target there
   before claiming MJX wins on Apple Silicon developer machines.

4. **PRB (Path Replay Backprop) supports BSDF gradients, not emitter
   position.** Attempting to optimize a point-light position via PRB
   triggers "contribution is not attached to the AD graph" because
   light-position derivatives are discontinuous (direct visibility). R1
   G5 measurement strategy should specify BSDF reflectance / scale /
   geometry parameters as the differentiable parameter, not light pose.

5. **`mj_ray` lidar proxy is single-threaded loop in Python**, ~5760 rays
   in <1s but not scalable. R2 binding to CARLA lidar kernel + Vulkan RT
   stays mandatory. The proxy validates the geometry pipeline only.

6. **USD references work cleanly for fleet composition.** A 4-instance
   `kusawake_fleet.usda` is 982 bytes (vs ~12 KB if each instance were
   expanded). R3 community-scale (≤30 units) fleet definitions should
   adopt USD reference graph from the start.

## Dimensions deliberately not exercised at preflight

These need the R1+ Murakumo-fleet binding before they can land:

- **G4 Murakumo fleet execution** — preflight runs on dev Mac, not fleet
- **G5 ≥ 0.75 vs Isaac Sim ground truth** — requires the isolated trial
  machine per ADR-2605261600 §G5 carve-out (one-time-use, decommissioned)
- **G6 `simulationRunAttestation` lexicon emission** — schema is R1 work
- **G7 cross-hardware bit-identical replay** — preflight covers same-hw only
- **G8 NVIDIA-account-required runtime tools** — vacuously true (we use none)
- **G10 Charter Rider §2 asset scan** — vacuously true (only primitive cubes
  and cylinders used; no asset-marketplace imports)
- **G11 simToRealHandoverAttestation** — requires R1 real-robot pilot
- **G13 telemetry-free build** — verified by inspection (no telemetry imports);
  formal compile-time disable lands at R1
- **Vulkan RT** — Apple Silicon is not a Vulkan RT platform; R2 EVO-X2 territory
- **HdCycles** — R1 binding; this harness uses Mitsuba 3 standalone
