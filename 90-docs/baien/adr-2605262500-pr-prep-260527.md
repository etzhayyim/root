The branch name suggests yakushi was the origin point, but ~10+ ADRs accumulated work here in parallel agent sessions. **It is not natively an ADR-2605262500 branch.**

### Three options

#### Option A — Cherry-pick to focused branch (RECOMMENDED)

Create new branch from `main`, cherry-pick the 26 ADR-2605262500-scope commits.

**Pros**:
- Reviewable scope (~26 commits, ~3.5k LOC delta)
- Clear ADR alignment (every commit traces to ADR-2605262500)
- Ships ADR-2605262500 cleanly without waiting for other ADRs
- Easy to add ADR-2605262500-only CI gates

**Cons**:
- Mixed-content "wave" commits (`chore(wave): …`) will pull in non-ADR-2605262500 files; would need partial cherry-pick or commit splitting
- 5 commits are "mixed wave" (`918e7df5f`, `4845d1704`, `67d2d5a0e`, `28d32f061`, `43351b5c2`); each needs surgery
- Original commit dates lost (cherry-pick replays as today's date unless `-x` + commit hooks negotiated)

**Estimated effort**: 2-3 hours of git surgery.

**Concrete command sequence** (DO NOT run without user authorization):
```bash
git checkout main
git pull origin main
git checkout -b feat/adr-2605262500-robotics-world-data-pipeline

# Clean cherry-picks (single-ADR commits):
git cherry-pick -x a77fda125 0dc1f9b16 5485234d8 3ee2e7d7f
git cherry-pick -x ed724c3c9 713d66e02 fdf92ba33 a9fcf88d6
# … (~21 more)

# Mixed wave commits require partial cherry-pick:
git cherry-pick --no-commit 918e7df5f
git reset HEAD -- <non-ADR-2605262500 paths>
git checkout -- <non-ADR-2605262500 paths>
git commit -m "feat(adr-2605262500): wave subset — robotics world data"
```

#### Option B — Push entire branch as bundle PR

Push `feat/yakushi-wave-1c-r1-commissioning` as one PR.

**Pros**:
- Zero git surgery
- Preserves full commit history + dates

**Cons**:
- 379 commits is **unreviewable** in practice
- Reviewer would have no way to scope-check
- ADR-2605262500 scope buried in noise

**Not recommended.**

#### Option C — Squash-rebuild

Create new branch from main, copy current state of ADR-2605262500-owned files (the working-tree snapshot), commit as one or a few logical squashed commits.

**Pros**:
- Easiest git operation (no cherry-pick conflicts)
- Reviewer sees clean diff vs main
- Can structure as W0 / W1 / W2 / W3 / W4 wave commits

**Cons**:
- Loses commit history detail (44 cycles collapsed)
- Loses "this fix happened because of that observation" causality
- Implementation retrospective doc partially mitigates this

**Estimated effort**: 30 minutes.

**Concrete command sequence**:
```bash
git checkout main
git pull origin main
git checkout -b feat/adr-2605262500-robotics-world-data-pipeline

# Copy ADR-2605262500-owned files from feat/yakushi-wave-1c-r1-commissioning
for path in <list of ADR-2605262500 paths>; do
  git checkout feat/yakushi-wave-1c-r1-commissioning -- "$path"
done

# Stage + commit as wave subsets:
git add 90-docs/adr/2605262500-*.md && git commit -m "feat(adr-2605262500): W0 — ADR + retrospective"
git add 70-tools/e7m-dataset/src/e7m_dataset/fetchers/ && git commit -m "feat(adr-2605262500): W1 — Tier-A + Tier-C fetchers"
git add 70-tools/e7m-sim/scripts/assemble*.py 70-tools/e7m-sim/scenes/ && git commit -m "feat(adr-2605262500): W2 — USD assembler + 9 scenes"
git add 70-tools/e7m-dataset/src/e7m_dataset/vision_pii*.py 70-tools/e7m-dataset/tests/test_vision_pii*.py && git commit -m "feat(adr-2605262500): W3 — Vision PII filter (3 ONNX backends)"
git add 70-tools/e7m-sim/scripts/eval_sim_metrics.py && git commit -m "feat(adr-2605262500): W4 — G11 quality gate eval CLI"
git add 70-tools/scripts/lint/ 70-tools/scripts/diagnose/ lefthook.yml .github/workflows/deps-toml-paths.yml && git commit -m "feat(adr-2605262500): operator UX + book-keeping enforcement"
git add 90-docs/baien/adr-2605262500-* deps.toml && git commit -m "docs(adr-2605262500): retrospective + runbook + smoke + deps.toml"
```

### Recommendation

**Option C (squash-rebuild) is the pragmatic best.**

Rationale:
- The 44-cycle implementation history is **already preserved** in
  `adr-2605262500-implementation-retrospective-260527.md` (39-cycle chronology)
  + `adr-2605262500-runbook-smoke-260527.md` (cycle 44 evidence).
- Reviewers care more about "does the end state work" than "what was
  the 7th iteration's debugging trail."
- Option A's git surgery has surface area for mistakes (the cycle 43
  re-commit incident is a real example).
- Option C cleanly maps to W0..W4 ADR wave structure, which is how
  the ADR itself is organized.

**Decision required from user before any branch action.**
