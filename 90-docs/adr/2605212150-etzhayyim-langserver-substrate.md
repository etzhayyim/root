# ADR-2605212150: etzhayyim-langserver — Fleet-resident LSP substrate on Murakumo Mac mini fleet

**Status**: proposed
**Date**: 2026-05-21
**Deciders**: Jun Kawasaki

## Context

Two converging pressures motivate a fleet-resident Language Server Protocol (LSP) substrate:

1. **Editor side (human developers)**: a developer working on any Mac mini in the
   Murakumo fleet (or on a roaming laptop joined to the mesh) should be able to
   open an editor against the substrate code and receive symbol-aware
   completion / hover / goto-definition / references / rename — without each
   mini re-indexing the same rust/python/typescript workspace locally.

2. **Cell side (Pregel)**: religious-corp Pregel cells (per ADR-2605192415) that
   manipulate code — refactoring, dependency-walking, charter-compliance
   verification — need a symbol-aware oracle. They currently lack one. A
   fleet-resident LSP that any cell can query closes this gap.

The Murakumo fleet (10 tribes — naphtali / simeon / judah / zebulun / levi /
joseph / issachar / dan / benjamin / asher; ADR-2605182312 + ADR-2605211910)
is the sole Tier 1 compute target per ADR-2605191346, with launchd-only
control plane per ADR-2605192415 §7.1. A self-hosted mesh (`50-infra/cluster/
murakumo/`, X25519 + XChaCha20-Poly1305, 10.99.0.0/16 mesh subnet) provides
fleet-wide L3 connectivity. The substrate to host LSPs and reach them
from anywhere on the mesh therefore already exists; what is missing is the
**glue** that turns "a fleet" into "a federated LSP service".

Reverse topological ordering of dependencies clarifies the build:

```
L1 host inventory      ←  L2 launchd plist   ← L3 LSP pins
   ↓                        ↓                    ↓
L4 socket / TCP listener ← L5 mesh-IP binding ← L6 health probe
   ↓                        ↓                    ↓
L7 observability         ← L8 editor bridge   ← L9 cell-runner integration
```

Each layer is independent of layers above it but closes a port for the layer
below. Building leaf-first lets each commit ship with self-contained value
and minimizes coupling.

## Decision

Introduce `50-infra/etzhayyim-langserver/` as a sibling of the existing
religious-corp infra modules (`etzhayyim-charters-compliance/`, `-tithe-router/`,
etc.). The module provides:

### A. Architecture

- **One LSP family per mini** (placement table below), chosen to avoid
  co-locating heavy LSPs with the existing PDS (simeon), LiteLLM gateway
  (judah), or heavy cron cells (levi).
- **launchd-only supervision**, mirroring `com.etzhayyim.kotodama-cell-runner.plist`
  conventions: `KeepAlive` on non-zero exit + network state, `ThrottleInterval`
  15s anti-flap, `ProcessType` Background, `Nice` 5.
- **socat fork mode** for transport: one LSP process spawned per client
  connection. Cold-start cost paid by client; workspace cache persists
  between sessions in the LSP's own cache directory.
- **Both Unix domain socket + mesh-IP TCP listeners** by default (`mesh-both`
  mode), so same-host editors get fast fs-permission auth and remote
  editors traverse the mesh.

### B. Placement

| Language | LSP | Host | TCP port | Healthz port |
|---|---|---|---|---|
| rust | rust-analyzer (`2026-01-13`) | joseph | 15510 | 15610 |
| python | pyright (`1.1.401`) | issachar | 15511 | 15611 |
| typescript | typescript-language-server (`4.3.4`) | dan | 15512 | 15612 |
| go | gopls (`v0.18.1`) | naphtali | 15513 | 15613 |
| lua | lua-language-server (`3.15.0`) | zebulun | 15514 | 15614 |
| ruby | ruby-lsp (`0.23.0`) | naphtali | 15515 | 15615 |
| _failover replica_ | (any) | asher | (dynamic) | (dynamic) |

solargraph is **explicitly not pinned** — superseded by Shopify ruby-lsp.
Port range 15500-15600 LSP / 15600-15700 healthz; reserved space for ~84
future languages.

### C. Single source of truth

`50-infra/etzhayyim-langserver/scripts/lsp-fleet.json` (generated by
`generate-fleet-registry.sh` from `hosts.toml` + `transports.toml` + `mesh.toml`)
is the **only** place mesh-IPs and ports appear in editor-facing config.
The shim `scripts/attach-langserver.sh` reads it at editor-invocation time.
Editor configs (nvim / Helix / Zed / VSCode) reference `attach-langserver.sh`
and the language identifier; they never encode IPs. Fleet topology changes
require only registry regen.

### D. Observability

Three signals to existing sinks; no new commercial vendor:

1. on-disk via launchd `StandardOutPath` / `StandardErrorPath`, rotated by
   macOS `newsyslog` (50 MiB × 5 archives, gzip);
2. Prometheus textfile at `/metrics` on the healthz sidecar — five metrics
   (`etzhayyim_langserver_up`, `_uptime_seconds`, `_probe_latency_seconds`
   {probe=tcp|deep}, `_probe_failures_total`, `_probe_total`) scrape-target
   `http://murakumo.etzhayyim.local:9090` (already in fleet.toml `[monitoring]`);
3. NATS JetStream forwarder (`scripts/ship-logs-to-nats.sh`) — **opt-in
   only**, default noop. Subject `etzhayyim.langserver.<host>.<lang>.<stream>`.

### E. Cell-runner integration

`40-engine/kotoba/crates/kotoba-kotodama/py/src/kotodama/primitives/langserver_client.py`
provides an asyncio-based LSP JSON-RPC client (stdlib only, no third-party
deps), exposing `initialize / shutdown / hover / definition / references /
rename`. The reference cell `LangserverHealthMonitoringCell` (registered
in `50-infra/cluster/murakumo/cell-runner/cells.toml` on levi, cron
`*/5 * * * *`, healthz 13028) concurrently probes every fleet LSP via real
LSP `initialize` handshake and records latency + advertised capabilities.

### F. Dry-run discipline (per CLAUDE.md)

Every generated artifact (plists, install scripts, NATS forwarder, attach
shim) is **dry-run-default**. `launchctl load` is gated on:

1. `scripts/probe-hardware.sh` committing `hw.*` blocks to `hosts.toml`
2. `scripts/install-langservers.sh --apply` succeeding per host
3. explicit user confirmation per CLAUDE.md "ハードウェア未確認段階では
   plist は dry-run のみ" constraint.

## Consequences

### Positive

- **Cell symbol-awareness** unlocks substrate-internal refactor / verification
  cells (e.g., a future `CharterRiderNoticeCell` that confirms a per-file
  NOTICE update via gopls / pyright references rather than regex).
- **Editor portability**: a developer can roam between minis (or attach
  from a laptop) without dragging workspace indexes — the index lives on
  the mini whose disk owns the source.
- **No new commercial dependency**: socat / Prometheus / NATS / newsyslog
  are Apache 2.0 (or BSD/MIT) OSS. Charter Rider applies to all
  first-party artifacts in this module via repo-root `/CHARTER-RIDER.md`.
- **Topology-change cost is one script run**: regenerate `lsp-fleet.json`,
  no editor config edits.
- **Health observability fits existing fleet conventions**: healthz
  port allocation rule (`port_lsp + 100`) mirrors cell healthz at 13000-14000
  + 100 offsets.

### Negative

- **socat fork mode pays cold-start per editor session**. rust-analyzer
  indexing of large workspaces is the dominant cost. A future multiplexer
  (`lsp-proxy` / `lsp-multiplexer`) can replace fork mode without changing
  transports.toml — left to a follow-up ADR when the cost becomes
  meaningful in practice.
- **Workspace divergence**: the fleet LSP indexes the workspace on the
  mini's disk, not the editor's local file tree. Developers editing
  substrate code must `git pull` on the mini (or run an editor session
  attached directly to the mini's workspace). Out-of-band workspace
  synchronization is **out of scope** for this ADR.
- **MST listener wiring deferred**: writing
  `LangserverHealthMonitoringCell` results to MST requires a new lexicon
  under `00-contracts/lexicons/com/etzhayyim/langserver/`. Captured in
  `deps.toml [platform.langserver.cell_integration].lexicon_status =
  "deferred"`; a follow-up ADR will register it.
- **NATS deployment dependency for stream-tier observability**: NATS is
  scaffolded (`50-infra/nats-jetstream-*`) but not yet live on every
  mini. The forwarder is opt-in and gracefully no-ops if the broker is
  unreachable.
- **mesh identity legacy path**: `~/.etzhayyim/mesh/identity.json` lives on
  current minis pending the cutover to `~/.etzhayyim/mesh/identity.json`.
  `langserver_client` reads either path; this is a temporary compatibility
  shim that disappears when the cutover lands.

### Constitutional & substrate-fit checks

- **State**: LSP is **computation only**. No MST / IPFS / L2 writes from
  this substrate. Passes ADR-2605172000 RW-free check.
- **Payment**: none. Passes ADR-2605172100.
- **License**: Apache 2.0 + Charter Compliance Rider v2.0 (per ADR-2605192200).
- **Operating entity**: all artifacts use `etzhayyim-` prefix. No `etzhayyim-`
  prefix in newly authored code. Per CLAUDE.md.
- **Eros / Gore / Force**: not applicable — developer tooling has no
  generative content surface.
- **Land trust**: not applicable.
- **Religious-corp daemon architecture (ADR-2605192415 §7.1)**: this
  substrate **adds** a peer to the existing launchd daemon family. It is
  not a religious-corp constitutional cell — placement on `levi` for the
  reference monitoring cell is a *workload* decision, not a constitutional
  binding.

## Alternatives Considered

### A. One LSP container image per language, pulled by every mini

Rejected. Container orchestration is forbidden per ADR-2605191346 (no
commercial K8s control plane). Standalone container runtimes (orbstack /
lima) exist but launchd already supervises the existing kotodama
cell-runner — adding a parallel control plane buys nothing.

### B. Run all LSPs on a single "tool box" mini

Rejected. The fleet's Wellbecoming axis (per ADR-2605192100 §1.13)
applies to infrastructure too: concentration risk on a single mini is a
flap-cascade risk. Distribution across 5 tribes (joseph / issachar / dan /
naphtali / zebulun) with `asher` as failover replica matches the
fleet's existing scheduling discipline.

### C. Editor-side LSP only (no fleet daemon)

Rejected for the Pregel-cell use case: cells can't drive an editor.
Rejected for the developer use case at fleet-scale: re-indexing rust
workspaces on every editor restart, per developer, per mini, multiplies
the indexing cost by N × M where the federated approach is O(1).

### D. Adopt commercial managed solution (e.g., Coder / Gitpod)

Rejected. ADR-2605191346 hard rule against commercial K8s control plane
+ Charter Rider §2(a)-(h) commercial-dependency category. OSS only.

### E. Use Tailscale instead of self-hosted mesh

Rejected. The fleet already runs `murakumo-mesh` (50-infra/cluster/
murakumo/, X25519 + XChaCha20-Poly1305). Reusing it avoids a second
identity/key system and a SaaS dependency (Tailscale control plane).

### F. Build a custom WebSocket LSP gateway

Considered for browser-based editor support. Rejected at this stage —
adds a JS runtime to the substrate; existing 4 desktop editors (nvim /
Helix / Zed / VSCode) cover the developer surface. Re-evaluate if a
browser editor (e.g., Theia, code-server) is requested.
