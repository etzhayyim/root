# etzhayyim/root docs — Documentation System Rules

`90-docs/` は **human-readable Markdown** を canonical source とし、機械可読な索引は sidecar registry に分離する。

## Goal

- 人間に読みやすい本文を維持する
- LLM が authoritative doc を短距離で見つけられるようにする
- Shannon redundancy を抑え、設計判断の重複と drift を減らす

## Canonical Structure

- 本文: `**/*.md` (repo-wide)
- decision record: `90-docs/adr/*.md`
- machine registry: `90-docs/_registry/docs.json` (pending — to be generated by tooling parity with vendor monorepo)
- relation graph: `90-docs/_registry/graph.jsonld` (pending)
- schemas: `90-docs/_registry/schemas/*.schema.json` (pending)

**CRITICAL**:

- Markdown 本文が canonical source。`90-docs/` 配下に限らず repo 全体の `.md` が対象
- JSON-LD は本文の代替ではなく relation/index sidecar
- 「同じ判断」を複数 doc に複写しない。正本 1 つを registry で指す

## ADR Placement Policy (THIS REPO IS CANONICAL FOR OPEN-SCOPE)

Per ADR-2605170900 (this repo) and ADR-2605152100 (vendor monorepo):

| Scope | Canonical home | Examples |
|---|---|---|
| **Open religious-corp activities** (blockchain / baien / bpmn / lexicon / pregel / atproto / ameno / open-data / public governance) | **`etzhayyim/root/90-docs/adr/`** ← here | new baien designs, new ameno features, new open-* app architectures, new bonsai metaphor extensions |

| **Vendor business operations** (lawfirm, malak case-anchored Pregels, akuma redteam authorization, finance, HR) | `gftdcojp/ai-gftd-apps-gftdcojp/90-docs/adr/` | ADR-2605151400, ADR-2605152000, ADR-2605151500 |
| **Shared foundational ADRs** (used by both repos) | `gftdcojp/ai-gftd-apps-gftdcojp/90-docs/adr/` (vendor historical), referenced by URL from etzhayyim/root | ADR-2604251830 Shannon-Optimal 8-Layer, ADR-2605091400 MCP-as-Cell-Membrane, Bonsai Cultivar series |

When in doubt, **new open-scope ADRs go here** (`etzhayyim/root/90-docs/adr/`). Don't dual-author across repos.

## Required Metadata For New Or Materially Updated Docs

新規 doc、または意味論が変わる更新を行う doc は、冒頭に YAML front matter を置く。

必須キー:

- `id`
- `title`
- `status` — `active` / `proposed` / `deprecated` / `superseded`
- `doc_type` — `explanation` / `reference` / `how-to` / `tutorial` / `adr`
- `topic`
- `authoritative` — `true` / `false`
- `last_verified`

推奨キー:

- `authoritative_for`
- `related` (URLs ok for cross-repo references)
- `supersedes`
- `superseded_by`
- `depends_on` (for ADRs)

## Authoritative Doc Rule

各 topic には authoritative doc を最大 1 つ置く。

- 深掘り比較、調査メモ、履歴保全は `authoritative: false`
- repo の現行判断を定める doc は `authoritative: true`
- 新しい判断で古い doc を置き換えたら `supersedes` / `superseded_by` を更新する

## ADR ID Convention

ADR ファイル名: `YYMMDDhhmm-<topic-slug>.md`

- `YYMMDDhhmm` = JST 作成時刻 (5-digit short year + month + day + 24h hour + minute)
- `<topic-slug>` = kebab-case 短い topic 名
- 例: `2605170900-etzhayyim-root-adr-canonical-home.md` (2026-05-17 09:00 JST)

ID 衝突を避けるため、vendor monorepo の ADR ID と被らないよう「ある程度離れた分」を狙う (vendor は 2605152000 系まで使用)。etzhayyim/root は 2605170000 系から開始。

## Section Order (for design/eval ADRs)

1. `Context`
2. `Decision`
3. `Consequences`
4. `Alternatives Considered`
5. `References`

## Cross-Repo Reference

vendor の ADR を参照する時は full URL を使う:


または relative path 付き raw GitHub URL:

```markdown

```

逆 (vendor から etzhayyim/root への参照) も同様 full URL で。
