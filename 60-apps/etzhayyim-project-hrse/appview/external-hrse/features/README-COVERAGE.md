# BDDテストカバレッジ測定ガイド

## 現状

BDDテストでカバレッジを測定する際に、以下の課題があります：

1. **循環依存の問題**: 動的インポートを使用しても循環依存が発生する可能性がある
2. **カバレッジ測定の制限**: c8が動的インポートされたコードの実行を追跡できない場合がある
3. **エラーハンドリング**: LLMServiceやRecordRouterServiceの初期化でエラーが発生する可能性がある

## 実装済みの内容

### 1. モック/スタブの設定
- `features/support/hooks.ts`: 環境変数のデフォルト設定
- `features/support/service-wrapper.ts`: 循環依存を回避するためのサービス関数ラッパー
- `features/support/test-helpers.ts`: テスト用のヘルパー関数

### 2. エラーハンドリング
- ステップ定義にエラーハンドリングを追加
- エラーが発生してもテストを続行できるように改善

### 3. 実際のサービス関数の呼び出し
- `callAnalyzeEmail`: Email Analyzerサービスを呼び出すラッパー
- `callRouteRecord`: Record Routerサービスを呼び出すラッパー

## 統合テストとして実行する方法

### オプション1: 実際のAPI/データベース接続を設定

1. **環境変数の設定**
   ```bash
   export OPENAI_API_KEY="your-api-key"
   export CONNECT_API_URL="http://localhost:8083"
   export GRAPHQL_API_URL="http://localhost:8082/graphql"
   ```

2. **バックエンドサービスの起動**
   ```bash
   # Goバックエンドを起動
   cd performers/services/graphql
   go run main.go
   ```

3. **BDDテストの実行**
   ```bash
   pnpm test:bdd:coverage
   ```

### オプション2: モックサーバーを使用

1. **MSW (Mock Service Worker) の設定**
   - `src/__tests__/mocks/` にMSWハンドラーを設定
   - BDDテスト環境でMSWを有効化

2. **モックデータの準備**
   - LLMServiceの応答をモック
   - RecordRouterServiceの応答をモック

### オプション3: テスト用のサービス実装を作成

1. **テスト用のLLMService実装**
   - 実際のAPIを呼び出さないモック実装
   - カバレッジ測定のため、実際のコードパスを実行

2. **テスト用のRecordRouterService実装**
   - 実際のデータベースに接続しないモック実装
   - カバレッジ測定のため、実際のコードパスを実行

## カバレッジ測定のベストプラクティス

1. **静的インポートの使用**: 可能な限り静的インポートを使用して、c8がコードの実行を追跡できるようにする

2. **エラーハンドリングのテスト**: エラーケースもテストして、エラーハンドリングのコードパスをカバーする

3. **統合テストとユニットテストの使い分け**:
   - ユニットテスト: Vitestを使用して個別の関数をテスト
   - 統合テスト: BDDテストを使用してエンドツーエンドのシナリオをテスト

## 次のステップ

実際のカバレッジを測定するには、以下のいずれかの方法を選択してください：

1. **実際のAPI/データベース接続を設定** (推奨)
   - 統合テストとして実行
   - 実際のサービス関数が実行されるため、正確なカバレッジが測定できる

2. **モックサーバーを使用**
   - MSWを使用してAPI呼び出しをモック
   - テスト環境でモックサーバーを起動

3. **テスト用のサービス実装を作成**
   - テスト専用のサービス実装を作成
   - 実際のコードパスを実行しながら、外部依存を排除
