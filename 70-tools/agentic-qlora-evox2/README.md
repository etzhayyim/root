# agentic-qlora-evox2 — agentic-capability QLoRA for gemma-4-26B-A4B on EVO-X2

Strengthen the **agentic capability** (tool use / function calling / multi-step
ReAct / structured output / self-correction) of **gemma-4-26B-A4B** via QLoRA,
on the owned **EVO-X2** node. Per **ADR-2605302359**.

Artifact: `baien-server-agentic-gemma4-26b-a4b-r<NN>` — server carve-out, **NOT**
the ≤12B edge baien (ADR-2605241900). Inference stays Murakumo-only (ADR-2605215000).

## Why EVO-X2 (not the Mac mini fleet) for 26B

26B-A4B 4-bit ≈14 GB does **not** fit a 16 GB Mac mini for training (no room for
grads/optimizer/activations), so data-parallel across the fleet is out. The
**EVO-X2 (AMD Ryzen AI Max+ 395, 128 GB unified — 32 GB VRAM UMA + 96 GB sys,
BIOS-re-carvable)** fits the whole QLoRA run in unified memory: no sharding, no
Council gate (own hardware). The Mac mini fleet is the right substrate for
≤12B *data-parallel* LoRA, not for fitting a 26B.

## The MoE-aware target set (the key idea)

Adapters go ONLY on what matters per param, chosen from the expert-activation
profiling (`90-docs/baien/datasets/moe-expert-activation/gemma-4-26B-A4B/`):

| group | params | LoRA? |
|---|---|---|
| attention `q/k/v/o_proj` | small | **train** |
| **shared/dense FFN** `gate/up/down` | **535M, always active** | **train** |
| router `mlp.gate` | ~11M | optional (`--train-router`, off by default) |
| **128 routed experts** `*.experts.*` | **22.84B** | **frozen** |

`gate_proj`/`up_proj`/`down_proj` exist in BOTH the shared FFN and every routed
expert, so `moe_targets.resolve_targets()` returns **full module paths** and
excludes anything under `.experts.` — naming bare leaves would wrongly adapt all
22.84B routed-expert params.

## Files

| file | purpose |
|---|---|
| `moe_targets.py` | MoE-aware LoRA target resolver (+ `--dry-run` param accounting) |
| `train_evox2.py` | peft + trl + bitsandbytes QLoRA trainer (4-bit nf4, bf16, grad-checkpoint) |
| `seed/agentic-tooluse-r0-seed.jsonl` | 12 hand-authored Gemma-chat tool-use traces (Apache 2.0, Charter-clean) |
| `harvest_traces.py` | harvest the repo's REAL tool surface → grounded traces (19 kotoba WIT funcs kqe/kse/auth/llm/evm/chain + kotodama `Invoke` methods). `--mode template` (deterministic) or `--mode teacher` (Murakumo Ollama gemma, never a vendor API) |
| `seed/harvested-traces.jsonl` | 20 harvested grounded traces (generated by `harvest_traces.py`) |
| `seed/agentic-r0-corpus.jsonl` | the R0 corpus = hand-seed + harvested (32 examples, 32 distinct tools) |
| `verify_routing.py` | post-train: diff pre/post `expert-classification.json` (collapse / drift / salience) |
| `../baien-moemoekyun-train/recipes/agentic/baien-server-agentic-gemma4-26b-a4b-r0.toml` | corpus recipe (seed + gated open sources) |

## Run (on EVO-X2)

```bash
# 0. BIOS: optionally re-carve UMA to give the iGPU more VRAM (e.g. 64-96 GB) for headroom.
# 1. env (ROCm torch + peft/trl/bitsandbytes-rocm, as in gemma-coder-distill)
# 2. dry-run the target resolver (no training) to confirm experts are frozen:
python moe_targets.py <hf-safetensors-gemma-4-26B-A4B>            # prints n_targets + frozen-expert B
# 3a. harvest the repo's real tool surface → grounded traces, build the R0 corpus:
python harvest_traces.py --out seed/harvested-traces.jsonl       # add --mode teacher for richer dialogues
cat seed/agentic-tooluse-r0-seed.jsonl seed/harvested-traces.jsonl > seed/agentic-r0-corpus.jsonl
# 3b. (optional) assemble a larger corpus via the recipe once open FC sources are Charter-scanned:
e7m-dataset assemble-corpus \
  --recipe ../baien-moemoekyun-train/recipes/agentic/baien-server-agentic-gemma4-26b-a4b-r0.toml \
  --annex-root /Volumes/260317/etzhayyim/annex-store \
  --out-dir /Volumes/260317/etzhayyim/datasets-staging/baien-server-agentic-gemma4-26b-a4b-r0
# 4. train:
python train_evox2.py \
  --model-id <hf-safetensors-gemma-4-26B-A4B> \
  --data /Volumes/.../assembled.jsonl \
  --out  /Volumes/.../baien-server-agentic-gemma4-26b-a4b-r0 \
  --r 16 --epochs 2
# 5. verify routing health (re-profile base + merged, then diff):
python verify_routing.py --before base/expert-classification.json --after merged/expert-classification.json
```

> **Prereq / honest caveat**: training needs HF **safetensors** weights — the
> `.gguf` is llama.cpp-inference-only. Confirm a safetensors repo for
> gemma-4-26B-A4B exists and set `--model-id` to it; if only GGUF exists, obtain
> the bf16/safetensors source first.
