# Reference llama-cli invocation for Murakumo fleet disk inference
# (Gemma 4 26B-A4B MoE @ Mac mini M4 16GB).
#
# Source: ADR-2605253000 §1.
#
# Why each flag:
#   -ngl 0              CPU/BLAS backend; Metal full offload fails at
#                       12.7 GB working set cap on M4 base 16GB
#   -c 2048             ctx 2048; ctx 4096 approaches 16GB RAM ceiling
#                       and risks swap thrashing
#   -fa 1               flash attention (saves KV cache memory)
#   -ctk q8_0           KV cache key  in q8_0 quantization
#   -ctv q8_0           KV cache value in q8_0 quantization
#   -t 4                4 threads (M4 has 4 P-cores; E-cores ignored)
#   -n 120              max 120 generated tokens (bench-friendly bound)
#
# Why this 3-flag set is MANDATORY for non-interactive run:
#   -no-cnv             disable conversation mode (gemma4 chat template
#                       forces interactive prompt `>` otherwise)
#   -st                 single-turn (exits after one response)
#   --simple-io         avoid TTY heuristics (subprocess-safe)
#   < /dev/null         stdin closed so any prompt waiter exits immediately
#
# Without all three, the 26B model loads + warms (~80 sec) then idle-waits
# at `>` indefinitely while consuming 92% CPU on warmup — verified failure
# mode 2026-05-25, see ADR-2605253000 §4.3.

llama-cli -m <path-to-gguf> \
  -ngl 0 \
  -c 2048 \
  -fa 1 \
  -ctk q8_0 \
  -ctv q8_0 \
  -t 4 \
  -n 120 \
  -no-cnv \
  -st \
  --simple-io \
  -p "<prompt>" \
  < /dev/null
