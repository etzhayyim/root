## 2. 実装（依存ゼロ・clj/bb）

`ecdsa_coscientist.clj` に secp256k1 体演算・点演算・ECDSA・整数保存 LLL を
**外部暗号ライブラリなしで自前実装**（リポ規約の clj/bb に準拠）。

- **攻撃A — nonce 再利用**：同じ `k` の2署名から純モジュラ演算で `k`,`d` を厳密復元
  `k=(z₁−z₂)/(s₁−s₂)`, `d=(s₁k−z₁)/r  (mod n)`。
- **攻撃B — 短い nonce（壊れた RNG）→ HNP/LLL**：`kᵢ=aᵢ+bᵢ·d (mod n)`,
  `0≤kᵢ<2¹²⁸` を格子に埋め込み、**Cohen Alg. 2.6.3 の整数保存 LLL**で短ベクトル＝
  `(…, d·K, K·n)` を取り出し `d` を復元（有理数の分母爆発を回避して高速）。

- **数学（ECDLP/secp256k1）は無傷**。健全に署名された鍵は本 PoC でも一切復元できない。

## 5. H2 実装結果 — Semaev 総和多項式 × index-calculus（`semaev_index_calculus.clj`）

記事の精神の純粋形（数学正面）を**実装して実測**した。小さい素体 E(F_p) 上で:

1. **Semaev S_3** を実装（`P1+P2+P3=O ⇔ S_3(x1,x2,x3)=0` を経験的に検証）。
2. factor base（x 座標が小集合 V にある点）を作る。
3. ランダム `R=uP+vQ` を **S_3 を 2 次式として解いて** `R=Pa+Pb` に分解 → 線形関係を収集。
4. **mod n ガウス消去**（ℓ_x 列を消去し d を読む）で離散対数を解き **d を復元 → dP==Q 検証**。

### 実証結果（小曲線で ECDLP を実際に破る）

```
E: y²=x³+2x+2 (mod 1031), n=971 素数, P=[0,473], 真の d=359
factor base |V|=42 → |FB|=25, Semaev 分解試行=846
>>> 復元 d=359 == 真の d=359  ✔  (~30ms)
```

### スケーリング計測（= secp256k1 が安全な理由の実測）

| p | n | \|FB\| | 分解試行 | ms | d一致 |
|---|---|---|---|---|---|
| 503 | 499 | 17 | 522 | 18 | ✔ |
| 2011 | 2003 | 40 | 1218 | 47 | ✔ |
| 8011 | 7937 | 60 | 7355 | 201 | ✔ |
| 20011 | 20147 | 92 | 19818 | 547 | ✔ |
| 50023 | 49843 | 143 | 46146 | 1192 | ✔ |

- **`|FB| ≈ √p`**（17→143 は約 √(99×)≈10× と一致）。
- **分解試行 ≈ O(p)**（522→46146 は約 88× ≈ p の増加 99×）。
- → 素体では関係収集 O(p) + 線形代数 O(|FB|³)=**O(p^1.5)**。**rho の O(√p) を超えない**。

### 結論 — secp256k1 への外挿

- index-calculus は確かに ECDLP を解く。**だが素体では rho より遅い**。
- secp256k1: `p≈2²⁵⁶ → |FB|≈2¹²⁸`, 線形代数 `≈2³⁸⁴ ≫ rho の 2¹²⁸`。
- Weil descent が効く拡大体/二進体と違い、**素体 secp256k1 はこの攻撃に構造的に安全**。
- 記事の AI（新パラメータ化）が刺さるのは『分解= S_m=0 を解く段』だが、素体では
  その段の改善が **線形代数 O(p^1.5) の壁を崩さない**。これが H2 を回した実測の核心。

実行: `bb --config /tmp/empty-bb.edn 70-tools/secp256k1-coscientist/semaev_index_calculus.clj`
